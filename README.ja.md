# AutoPost Guide — 記事を書けば、あとは全部自動で流れる

コミュニティ・活動紹介サイト向けの**手法ドキュメント**です。WordPress で記事を
1本公開すると、サイトのトップ「What's New」への掲載と、Facebook ページへの
投稿が**どちらも自動で**行われる——その構成の作り方・検証のしかた・実際に
踏んだ罠を記録しています。

[English README is here](README.md) /
[www.rumicar.com](https://www.rumicar.com/) で 2026年8月に構築・検証した
構成の記録です。姉妹プロジェクト
[PhotoStrip](https://github.com/RumiCar-group/RumiCar-PhotoStrip)・
[VideoLoop](https://github.com/RumiCar-group/RumiCar-VideoLoop) がコードの
公開だったのに対し、これは**やり方の公開**です。コードはほとんど出てきません。

> **最初に読む位置づけの話**: 本書は 2026年8月時点で実際に動いた**一例の記録**
> であり、動作の保証ではありません。登場するサービスの UI・API・料金は変わり

## 解決したかった問題

私たちのクラブのサイトには、イベント報告や技術記事が少しずつ増えていきます。
記事を1本公開するたびに、同じ手作業が付いてきます——トップページの更新と、
Facebook ページへの告知投稿。この「公開後の手作業」を仕組みごと無くして、
書くことだけに集中したい、というのが動機です。

要件はシンプルです:

1. 記事を「公開」した瞬間から先は、人間の作業ゼロで流れること
2. サイトのトップに新着として載ること
3. Facebook ページに投稿されること(リンクカード付きで)
4. 本当に流れたかを、**推測でなくログで**確認できること

## 全体像

```
記事を公開 (WordPress)
   │
   ├─→ What's New に自動掲載 ……… サイト内。新着 N 件のクエリを置くだけ
   │
   ├─→ OGP メタ出力 ……………………… シェア時のリンクカードの材料
   │
   └─→ RSS フィード (/feed/) ………… WP 標準。何もしなくても出ている
          │
          ▼
      dlvr.it が RSS をポーリング (数分〜30分間隔)
          │
          ▼
      Facebook ページへ自動投稿 (タイトル + リンクカード)
```

前半3つは WordPress の中の話、後半は外部サービス(RSS→SNS 連携)の話で、
**WP 側から連携サービスへ渡るものは RSS フィードだけ**です(投稿成立後には
Facebook 側がリンクカード生成のため記事 URL を直接読みに来ます——罠3参照)。
この疎結合が肝で、WP 側とサービス側を独立に検証・交換できます。

## 前提 — 必要なもの

**RSS フィード。** WordPress 標準機能で、`https://あなたのサイト/feed/` に
最初から出ています。テーマやプラグインで止めていなければ、追加作業はありま
せん。多言語サイト(Polylang 等)ではフィードが言語別に分かれます
(`/feed/` = 既定言語、`/en/feed/` = 英語)。rumicar.com では日本語フィード
だけを接続しています(英語フィードは意図して未接続)。

**OGP メタタグ。** Facebook 投稿のリンクカード(画像+タイトル+説明)は、
記事 URL の OGP メタ(`og:title`, `og:image` 等)から作られます。SEO 系
プラグインか自作コードで出力されていれば十分です。整っているかは
[Meta の Sharing Debugger](https://developers.facebook.com/tools/debug/) で
記事 URL を1本入れると確認できます。

**What's New(トップの新着欄)。** 仕組みとしては「公開済みの記事を新しい順に
N 件」のクエリをトップページに置くだけです。実装はテーマの新着ウィジェット
でも、プラグインでも、数行の自作でも成立します。rumicar.com は自作で、
概念としては:

```php
// 概念例: 公開済み記事を新しい順に5件
$q = new WP_Query([ 'post_status' => 'publish',
                    'posts_per_page' => 5, 'orderby' => 'date' ]);
```

多言語サイトの場合の実装判断を1つ共有すると: 現在の言語で絞って 0 件に
なったとき、rumicar.com では空欄にせず「他言語の新着を注記付きで出す」
フォールバックにしています。

**Facebook ページ。** 自動投稿の届け先は(個人プロフィールではなく)
Facebook ページで、接続時にそのページの**管理者権限**で認可します。ページが
まだ無ければ、先に作成しておく必要があります。

## 手順 — dlvr.it の接続(2026-08-11 実施時の UI)

RSS→SNS の中継には [dlvr.it](https://dlvr.it/) を使いました。以下は実施
時点の画面構成で、変わっている可能性があります。

1. dlvr.it にサインアップ(無料トライアル 14 日。以降のプランは要確認 —
   トライアル終了日を控えておくと、切れて初めて気づく事態を避けられます)
2. Automate → New Automation → **Step 1 Input** で「RSS Feed」を選び、
   フィード URL(`https://あなたのサイト/feed/`)を入力
3. **Step 2 Outputs** で「Facebook (Page)」を選び、FB ページの管理者として
   OAuth 認可 → 対象ページを選択
4. **Step 3 Review** → Start

これで完了です。以降、フィードに新しい記事が現れるたびに、タイトル+リンク
カードの投稿がページに流れます。

なお同種の RSS→SNS 連携サービスは他にもあります(Buffer、IFTTT、Zapier
など)。本書は dlvr.it で構築した記録であって、特定サービスの推奨では
ありません。

### Meta 公式 API を選ばなかった理由

Facebook への自動投稿は Meta の Graph API を自前実装する道もあります。
比較した上で外部サービス方式にしたのは、公式 API 方式にはアプリ審査と
アクセストークンの定期更新という**維持コスト**が乗り続けるためです。外部
サービス方式は、ページ管理者としての認可1回で済みます。少人数で運営する
小さなサイトでは、この差が効きます(組織で審査・運用体制があるなら公式 API
の方が自由度は高い——優劣ではなくトレードオフです)。

## 罠と検証 — 実際に運用して分かったこと

ここが本書の存在理由です。設定手順は前節までのとおりですが、以下は実際に
動かして初めて分かったことです。

### 1. 有効化した瞬間、最新記事が1回投稿される

Automation を Start すると、フィードの最新記事がその場で1本投稿されます。
その記事を既に手動でページに投稿していた場合、**ページ上で同じ記事が2回
並びます**。rumicar.com でも発生し、自動投稿側を削除して解消しました。
有効化の直後にページを一度見ておくと、この重複にすぐ気づけます。

### 2. 「パブリッシャー: dlvr.it」の表記は管理者にしか見えない

自動投稿には投稿元表記が付きますが、これは**ページ管理者の画面にだけ**表示
されます。一般の閲覧者には通常の投稿として見えます。「自動投稿だと機械っぽく
見えないか」という心配への、実測からの回答です。

### 3. 本当に動いたかはサーバーログで確認できる

連携サービスの管理画面を信じる以外に、**自分のサーバーのアクセスログ**で
一部始終を観測できます(生のアクセスログを参照できるサーバー環境が前提
です)。見えるのは2種類のアクセスです:

```
dlvr.it/1.0 (+http://dlvr.it/fetcher)     ← /feed/ を取得しに来る(ポーリング)
facebookexternalhit/1.1                    ← 投稿成立後、記事 URL を取得しに来る
                                             (リンクカード生成のため)
```

決め手は2つ目の**アクセス先 URL に `?utm_source=dlvr.it&utm_medium=facebook`
が付いている**ことです。これは dlvr.it が投稿に付けるパラメータなので、
「utm_source=dlvr.it 付きの FB クローラ来訪」=「Facebook 投稿が成立した」
の証拠になります。連携側の画面を開かずに、投稿成功をログだけで確認できます。

実測例(2026-08-11、時刻は UTC): dlvr.it fetcher が 09:54–55 に /feed/ を
取得 → facebookexternalhit が 09:55–57 に utm 付きで記事を取得 → 10:02 に
dlvr.it から「Your First Post is Live!」メール。

### 4. utm パラメータで流入を区別できる

3 の副産物として、自動投稿経由のアクセスには常に `utm_source=dlvr.it` が
付くため、アクセス解析で「FB 自動投稿から来た訪問」を手動シェアと区別して
数えられます。

### 5. キャッシュ層があると反映は遅れる

ページキャッシュ(rumicar.com は FastCGI cache 30分)を使っていると、
What's New への反映も RSS フィードの更新も、キャッシュ期限まで見えない
ことがあります。「公開したのにフィードに出ない」の第一容疑者はキャッシュ
です。dlvr.it のポーリング間隔(数分〜30分)も乗るので、公開から FB 投稿
までは最大で「キャッシュ期限+ポーリング周期」の遅延が見込みになります。
その意味で要件1の「公開した瞬間から」は、正確には「公開から数十分以内に」
と読むのが実態です。即時性が要る告知だけは手動で投稿する、という使い分けが
現実的です。
